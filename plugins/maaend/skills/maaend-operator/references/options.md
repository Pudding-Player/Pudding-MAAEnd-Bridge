# 选项含义与依赖

从本次声明读取选项的显示含义、类型、允许值、默认、输入约束、分支及适用对象。保存配置中没有某项值时，按当前声明判断默认或继承；不能把缺省一律当成关闭，也不将所有选项拍成无条件的一组值。

单选、多选、开关和输入各有不同结构；分支选择可能引入嵌套选项。某个分支下的有效值不自动适用于其他分支，未启用分支的旧记录也不一定影响本次执行。不要从显示标签反推底层结构或只凭字段名解释单位。

任务自身、通用声明、资源和控制器可能共同贡献选项。桥按宿主规则生成实际覆盖，模型只提交声明允许的选择，不手工拼底层流程、不自行猜测覆盖顺序，也不把运行参数生成说成已经在游戏中执行。

选项声明解释允许的输入，不一定展示完整的识别、动作与业务分支。要分析实际行为，应核对相应版本的任务资料或已授权源码，跟踪启用条件及调用位置；仅凭默认值、输入占位或声明标签不能证明游戏中必然发生什么。

热键设置是声明参数，不是实时键鼠操作。组合键、目标平台和控制器约定由当前声明与桥处理，不能自行把按键名换算成某个固定平台的数值，更不能据此声称已经按下了键。

敏感输入与加密保存值不回显、不恢复。只剩密文且桥没有受支持的获取方式时，明确当前提交受限，不按空值代替、不要求用户把凭据发给模型，也不修改认证设置来凑出可运行状态。

只改用户要求的已有选项，保留其他条目与未涉及分支。保存后核实实际值，生效范围和本次运行是否采用这些值还须按当前契约判断。
