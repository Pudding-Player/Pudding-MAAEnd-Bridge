# 准备、提交与停止

从当前任务说明核对所需实例、控制器、资源、执行器及可能的准备行为。只解释、查配置或保存入口时不初始化环境；真正执行也不擅自创建实例、重连控制器或装载另一份资源。

运行既有选中条目，沿用保存选项及当前声明的默认值，确认启用与兼容条件。只有现行受控入口明确负责的准备才随本次授权执行。声明要求的辅助执行组件由宿主按已保存信息准备，模型不能补造可执行文件、工作目录、环境或原始流程。

接纳必须有与本次提交相符的执行回执，不能只看网络请求成功。一组返回的执行记录只证明提交被接下，尚不证明任务已经完成；回执损坏、数量不符或响应丢失时保持未知，不能当作未运行再试一次。

普通启动到真实接纳后结束本轮，不额外读状态或日志监控。当前桥提供实例状态和任务结果读取，没有专用的业务完成等待或事件订阅入口。用户要求等结果时，核对外层任务系统能否按本次执行记录表达受控等待；没有对应链路就说明缺口，不能拿固定时长、全局空闲或反复请求模型替代完成。

停止针对实际运行的目标实例，提交后按回读判断。未确认停止、任务仍在运行及状态不可读分别说明，不把网络返回成功或取消等待说成已停止，不关闭宿主或杀进程来伪造结果。

明确未提交时按已知原因处理，不以相同参数盲目重发；结果未知先只读核实。多项运行保持用户顺序与各自失败处理要求，不能因为前项接纳就提前认为可以进入“完成后”的下一步。
