# 执行记录与业务结果

宿主总览、实例状态、执行记录和游戏内结果有不同粒度。框架正常不证明某项任务成功；一个实例恢复空闲，也不能区分尚未开始、自然结束、取消、异常或业务目标已完成。

按本次实例、选中条目、提交记录和观察时刻建立对应。多条任务回执应与本次实际提交内容匹配，不能把另一次运行或另一个实例的成功当成本次结果，也不能把声明任务身份当成执行记录身份。

接纳只说明请求被接下。任务进入运行、执行终结和游戏目标达成要用各自明确证据；没有业务结果时不能声称资源消耗完成、挑战成功或奖励到账。回执缺失、结果暂空、查询失败和实际失败分别处理。

用户要求跟进时读取必要范围，并保留每项真实结果。某一项失败不应被其他任务成功覆盖，组合中后续动作尚未执行时要说明，不能用一条总览状态代替整组结果。

停止核验只证明停止阶段，不证明此前游戏动作没有发生。取消等待也不撤销已经接纳的任务。查询不到时如实保持未知，不能再次运行同一任务来验证上次是否成功。
